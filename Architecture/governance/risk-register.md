# Risk register

Mutable document. Update it in the same pull request that adds, mitigates or closes a risk.
Last updated: 2026-10-04 (owner decisions on /ws, PIN, lawful basis). Findings marked "code review 2026-10-02" come from a read of
version 1.7.1; check the code before acting on them, it may have moved.

**Impact / likelihood:** H high, M medium, L low. **Status:** Open, Accepted (owner's deliberate trade-off),
Mitigating (work in progress), Closed.

| ID | Risk | Principles | Impact | Likelihood | Status | Mitigation / owner |
|----|------|-----------|--------|------------|--------|--------------------|
| R-01 | The field machine is a single point of failure: if it dies, tracking stops and data since the last backup is lost. | TP-03, BP-01 | H | M | Open | Backups before every migration and on demand; tested restore scripts. ⚠️ Owner: RTO/RPO, spare laptop and periodic backups to a separate drive are not defined (technology document 4.1). |
| R-02 | `/ws` is not authenticated: whoever reaches the backend receives all positions, SOS alerts and names (fire alerts add rescuer distances). | DP-01, DP-02 | H | L | Accepted (by design, ADR 15) | Every listener on loopback (ADR 12); revisit ADR 15 before any non-loopback binding. |
| R-03 | CORS allows every origin. | DP-02 | M | L | Accepted | Restrict origins (`todo.md`). Likelihood low while every listener is on loopback (ADR 12); rises to M if any binding changes. |
| R-04 | Street, Dark, Satellite and Topo basemaps and the weather overlays need the internet; without it the operator has only BG Mountains (offline mode) or a blank map. Starlink is standard, so online layers usually work, but the link can drop. | TP-01, BP-01 | H | M | Open | Local tile option for the basemaps operators rely on; mark online-only layers in the UI (Phase E). |
| R-05 | ~~The OpenWeatherMap API key is built into the browser bundle~~ (fixed: the backend proxies `/api/weather/*` and holds the key). Weather requests still send the map centre (area of operation) to a third party. | DP-01, DP-02 | M | M | Open (key part closed) | Key: done. Map centre: document as online-only (Phase E). |
| R-06 | Hardware path: a frame can be marked as seen before it is stored, so a database error followed by the gateway's retransmit loses the position while the device still gets an ACK (code review 2026-10-02). | BP-01, BP-03 | H | L | Open | Mark frames as seen only after they are stored; store a frame in one transaction. Must be validated against real hardware. |
| R-07 | The gateway gets an ACK for frames from unknown or inactive devices and for no-fix frames that are not stored (code review 2026-10-02). | BP-01 | M | M | Open | Decide and document which frames are ACKed; log every frame that is not stored. Hardware validation needed. |
| R-08 | Default `admin` / `admin` login with no forced change; no login rate limit. | DP-02 | H | M | Open | Force a password change on first login; rate-limit login. |
| R-09 | Volunteer photos under `/uploads` are served without authentication. | DP-02 | M | M | Open | Serve photos through an authenticated endpoint. |
| R-10 | PDF export needs the GTK/Pango runtime on Windows, which `pip` does not install; without it PDF export fails. | TP-03 | M | H | Open | Document or bundle the runtime; test a real render on Windows (`todo.md`). |
| R-11 | The backend and frontend run as development servers started by hand; nothing restarts them after a crash or reboot. | TP-03, BP-01 | H | M | Accepted (ADR 14) | Service unit / scheduled task and a built frontend (`todo.md`: build and compile). |
| R-12 | The tile server container restart-loops with the current image (`--no-config` no longer accepted). | TP-01 | M | H | Open | Pin the image and fix the command, or remove the service if unused (`todo.md`). |
| R-13 | The EFFIS/GWIS service can change layer names or go offline; the old `/effis` hotspot layers are already frozen. | TP-02, BP-01 | M | M | Mitigating | Fixed layer names in one place, last good data kept with its age, feed status shown (EFFIS plan P1/P2). |
| R-14 | After a restore the previous database stays as `<db>_before_restore_<time>`, a second copy of all personal data. | DP-03 | M | M | Open | Remind the operator to drop it, or offer a cleanup command (`todo.md`). |
| R-15 | The RescuerBee frame interval and device count per operation are unknown, so data volume and delay targets are guesses. | BP-01 | M | M | Open | Confirm with the hardware owner (`todo.md`). |
| R-16 | Retention periods for position history and backups are not defined. | DP-03 | M | M | Open | ⚠️ Owner decision; then implement retention keyed on `received_at` (`todo.md`). |
| R-17 | The response to an alarm happens by radio; the system keeps only who resolved it, when, and a optional note. After-action review relies on memory. | BP-02 | M | M | Accepted (ADR 3) | Ask for a short note on resolve; revisit if after-action reports become required. |
| R-18 | No operation entity: data and device assignments carry over between operations; per-operation reports are manual time-range exports. | DP-03 | L | H | Accepted (ADR 4) | Admin reviews assignments before each operation; revisit if per-operation retention is required. |
| R-19 | Special-category data (blood type, GDPR Article 9) is stored without a confirmed lawful basis; the ASP contract covers only ordinary personal data (ADR 16). Partner personnel are not under that contract. No data protection officer. | DP-01, DP-02, DP-03 | H | M | Open | ⚠️ Owner with legal advice: confirm an Article 9 basis, collect blood type with explicit consent, or remove it; decide the basis for partner personnel; name who handles access and deletion requests. |
| R-20 | Operation data must be preserved (BR-09), but the retention cleanup deletes positions after 90 days by default. | DP-03, BP-03 | H | H | Open | ⚠️ Owner: set the retention period; until then raise `location_retention_days` or export after each operation. |
| R-21 | ~~`users.pin` stored in plain text~~: the PIN is the volunteer's identification PIN, an identifier, not a secret (owner, 2026-10-04). `pin_hash` is unused. | DP-02 | L | L | Closed | Optional: drop the unused `pin_hash` column in a later migration. |
| R-22 | The `location_update` WebSocket message carries phone and photo path with every position to every `/ws` client. | DP-01, DP-02 | M | L | Accepted (by design, ADR 15) | Loopback only (ADR 12); a reduced payload is the option if exposure ever changes. |
| R-23 | Reads are not restricted by role. Login is now limited by `LOGIN_ROLES` (default `admin`, B47), so only admins get a session. | DP-02 | M | L | Closed | Keep `LOGIN_ROLES=admin`; widening it reopens this risk. |
| R-24 | The serial reader and the HID reader both start on every boot (both stay, owner 2026-10-03); behaviour when both see the same frame is untested. | BP-01 | L | L | Open | Configure which gateway paths run, or store a frame seen twice once; validate with real hardware. |
| R-25 | Field updates run `git pull` and dependency installs over Starlink; `requirements.txt` uses `>=` ranges and `start.ps1` runs `npm install`, so the field can get untested dependency versions. | TP-03, BP-03 | M | M | Open | Check out release tags only; use `npm ci`; add a constraints file for Python; never update during an operation (ADR 14). |
